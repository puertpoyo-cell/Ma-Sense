# PROPOSAL U1 — 사용성 기반 업데이트 (2026-10-31 제안, 사람 승인 대기)

2026-10-30 사람 요청 "사용성 기반으로 한 번 더 업데이트 고민". 새 기능보다 **이미 있는 흐름에서 손이 걸리는 곳**을 줄이는 데 집중한다.
근거는 이번 주 실기기 스크린샷(빌드 15~21)과 코드 확인. 금지선(COMPLIANCE.md)에 닿는 항목은 없다. 부위 추천·용량·목표 관련 제안은 일부러 넣지 않았다.

우선순위: **A 바로 고칠 걸림돌 → B 기록을 더 빨리 → C 찾고 이해하기 → D 접근성**. 각 항목 끝 괄호는 예상 규모(S 반나절 이하, M 하루, L 이틀 이상).

## A. 바로 고칠 걸림돌 (스크린샷에서 확인)

- **A1. 떠 있는 탭 바가 마지막 카드를 가림** (S)
  - 근거: 오늘 화면 "알아 두기" 부제가 탭 바 뒤로 잘림, 리포트 미리보기 아래 줄(단백질·근력운동·제지방량)이 탭 바에 덮임
  - 바꿈: 스크롤 아래 여유를 고정 32pt 대신 탭 바 높이만큼(`safeAreaPadding`/`contentMargins`). 네 탭 공통
- **A2. 마선생 팝업이 카드 글자를 덮고, 주제 칩이 화면 밖으로 잘림** (S)
  - 근거: 팝업이 "알아 두기" 카드를 반쯤 덮음, "오늘 뭐부터 할까요·단백질은요·…" 칩 세 번째가 오른쪽에서 끊김
  - 바꿈: 팝업이 떠 있는 동안 스크롤 아래 여유를 팝업 높이만큼 늘려 마지막 카드까지 올려 볼 수 있게. 칩 줄 오른쪽 끝을 흐리게 해 밀어 볼 수 있다는 걸 보임
- **A3. 리포트 기간 "직전 진료…" 잘림** (S)
  - 바꿈: 세그먼트 글자를 "진료 이후"로 짧게(VoiceOver는 "직전 진료 이후" 그대로)
- **A4. 리포트 미리보기 글자가 폰에서 읽히지 않음** (M)
  - 근거: A4를 화면 폭에 줄여 7~8pt 글자가 2~3pt로 보임
  - 바꿈: 미리보기를 누르면 전체 화면으로 열고 핀치 확대·이동. 공유 전에 내용을 직접 확인할 수 있게
- **A5. 빠른 기록 "체중" 아래 점의 뜻이 안 보임** (S)
  - 근거: 오늘 했다는 표시(N-D)인데 설명이 없음
  - 바꿈: 점 대신 작은 체크 아이콘, VoiceOver "오늘 기록함"

## B. 기록을 더 빨리 (매일 쓰는 흐름)

- **B1. 기록 직후 되돌리기** (M)
  - 지금: 잘못 누르면 기록 탭 → 그날 → 길게 눌러 지우기까지 4단계
  - 바꿈: "기록했습니다" 토스트에 "되돌리기"(4초). 수분·식이섬유·수면 토글, 단백질, 운동, 체중 직접 입력 공통
- **B2. 단백질 최근 항목 한 번에** (M)
  - 바꿈: 단백질 시트 맨 위에 최근 입력 3개를 칩으로("닭가슴살 1개 · 약 23 g"). 누르면 같은 끼니로 바로 기록. 새 저장 항목 없음(기존 기록에서 뽑음)
- **B3. 체중 직접 입력 기본값** (S)
  - 바꿈: 마지막 측정값을 미리 채우고 ±0.1 스테퍼. 키패드 없이 두세 번 눌러 끝
  - 주의: 이전 값과의 차이는 숫자로만, 색·평가 없음

## C. 찾고 이해하기

- **C1. 몸 추이 그래프에서 그날로 이동** (S)
  - 바꿈: 그래프에서 고른 날의 값 표시를 누르면 아래 하루 카드가 그날로 바뀜(같은 기록 탭 안)
- **C2. 핀치를 모르는 사람을 위한 기간 버튼** (S)
  - 근거: 핀치는 발견하기 어렵다(설명은 각주에만)
  - 바꿈: 제목 옆 "12주" 글자를 누르면 기간 메뉴(2주~전체). 핀치와 같은 단계, 같은 저장값
- **C3. 첫 실행 빈 카드에 첫 행동** (M)
  - 바꿈: 체중·단백질·진료 카드가 비어 있으면 설명 대신 "체중 적기", "건강 앱 연결" 같은 버튼 하나

## D. 접근성

- **D1. 몸 추이 그래프 VoiceOver 오디오 그래프** (M)
  - 바꿈: Swift Charts `accessibilityChartDescriptor`로 선마다 값 읽기·소리 그래프. 지금은 "몸 추이 그래프" 한 줄만 읽힘
- **D2. 큰 글자에서 빠른 기록 4칸이 좁음** (S)
  - 바꿈: 접근성 글자 크기에서는 2×2로

## 제안 순서

1. A1~A5, C2 (한 빌드, 대부분 S)
2. B1, B3, C1 (한 빌드)
3. A4, B2, C3, D1, D2 (한 빌드)
